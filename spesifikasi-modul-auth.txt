1. KONTEKS PROYEK
----------------------------------------------------------------
Sistem LMS untuk sekolah TK, instalasi tunggal per sekolah (bukan
SaaS/multi-tenant). Arsitektur: Laravel 13, Modular Domain-Driven
Design (folder app/Modules/), prinsip Action-based (1 class =
1 fitur bisnis). Controller HANYA menerima input dan mengembalikan
respons — logika bisnis WAJIB ada di dalam folder Actions/.

Namespace modul memakai PSR-4 custom di composer.json:
    "Modules\\": "app/Modules/"
Jadi penulisan namespace standarnya "Modules\NamaModul\...",
BUKAN "App\Modules\NamaModul\...".

Model User TIDAK ditaruh di dalam modul manapun. User adalah
shared kernel di App\Models\User (dipakai lintas banyak modul
untuk audit/akses — Finance, Student, Auth sekaligus). Model User
sudah memakai trait Spatie\Permission\Traits\HasRoles.

Baru direncanakan dua jenis pengguna sistem, dengan cara login BERBEDA:
  a) Superadmin — role "superadmin" (Spatie), login pakai
     email + password, session-based (guard "web"), akses ke
     halaman Blade admin panel.
  b) Orang tua/Wali — role "parent" (Spatie), login via API
     (guard "sanctum", akan dikonsumsi oleh frontend Vite React
     terpisah), dengan DUA metode login: (1) OTP dikirim ke nomor
     WhatsApp, atau (2) password biasa (opsional, untuk kondisi
     tanpa sinyal/pulsa).
Seeder pada tabel role spatie untuk dua role tersebut sudah dibuat.

Alur bisnis penting yang HARUS dipatuhi (jangan dibuat generic
"user bisa register bebas" seperti Laravel Breeze default):
  - Data siswa & profil orang tua (tabel `parents`) diinput
    LEBIH DULU oleh staff sekolah lewat admin panel. Baris
    `parents` dibuat dengan user_id = NULL (akun belum ada).
  - Orang tua mengaktivasi akun sendiri lewat aplikasi (nanti pakai
    React), dengan memasukkan nomor HP. Sistem mencocokkan nomor
    itu ke `parents.phone_number` yang SUDAH ada. Kalau tidak
    ketemu, tolak dengan pesan "nomor belum terdaftar, hubungi
    pihak sekolah" — JANGAN buat akun baru sembarangan dari nomor
    yang tidak dikenal.
  - Setelah OTP aktivasi valid, baru baris `users` dibuat dan
    di-link ke `parents.user_id` yang sudah ada, lalu role
    "parent" di-assign otomatis.
  - Admin TIDAK bisa self-register. Akun admin dibuat lewat
    seeder/Tinker manual oleh developer/pemilik sistem.

3. YANG PERLU DIBANGUN (SCOPE PEKERJAAN INI)
----------------------------------------------------------------

## A. Models
  [ ] Tidak ada model baru yang dibutuhkan — semua sudah ada.

## B. Migrations
  [ ] Cek apakah kolom users.password perlu tetap NOT NULL atau
      nullable (untuk kasus parent yang mungkin belum pernah set
      password kalau cuma pernah login via OTP) — putuskan dan
      sesuaikan migration bila perlu.

## C. Actions (folder: app/Modules/Auth/Actions/)
  [ ] GenerateOtpAction
      - Generate kode OTP 6 digit angka random.
      - Simpan ke otp_codes sesuai action_type (login/activation/
        reset_password).
      - WAJIB validasi: kalau action_type = activation, wajib
        isi phone_number dan user_id harus NULL. Kalau action_type
        login/reset_password, wajib isi user_id.
      - WAJIB cek rate limiting: tolak generate baru kalau nomor
        yang sama sudah minta OTP dalam 60 detik terakhir (query
        ke otp_codes pakai index [phone_number, created_at] atau
        [user_id, created_at]).
      - Set expires_at = now()->addMinutes(5).
      - Panggil Notification (lihat bagian F) untuk kirim ke WA.

  [ ] VerifyOtpAction
      - Terima input: phone_number/user_id, otp_code, action_type.
      - Query berbeda tergantung action_type (activation pakai
        phone_number, selain itu pakai user_id) — lihat contoh
        query yang sudah didiskusikan sebelumnya sebagai acuan.
      - Cek: is_used = false, expires_at > now(), otp_code cocok.
      - Kalau valid, set is_used = true, return sukses.
      - Kalau tidak valid/kedaluwarsa, lempar exception pesan
        jelas ("Kode OTP salah" / "Kode OTP sudah kedaluwarsa").

  [ ] ActivateParentAccountAction
      - Dipanggil SETELAH VerifyOtpAction sukses untuk
        action_type = activation.
      - Cari baris `parents` berdasarkan phone_number yang sudah
        diverifikasi. Kalau tidak ketemu, lempar exception.
      - Buat baris users baru: phone_number, password (opsional
        default random atau diminta set di step berikutnya).
      - Update parents.user_id dengan id user yang baru dibuat.
      - Assign role "parent" via Spatie.
      - Return User yang sudah aktif, siap dipakai untuk generate
        token Sanctum di Controller.

  [ ] AuthenticateAdminAction (SUDAH ADA — review saja, tambahkan
      rate limiting percobaan login gagal beruntun kalau belum ada)

  [ ] AuthenticateParentWithPasswordAction
      - Mirip AuthenticateAdminAction tapi untuk role "parent",
        guard sanctum (return User + buat token, bukan
        Auth::attempt session).

  [ ] AuthenticateParentWithOtpAction
      - Alur: VerifyOtpAction (action_type=login) -> ambil User
        terkait -> buat token Sanctum.

  [ ] ResetPasswordWithOtpAction
      - Untuk parent: VerifyOtpAction (action_type=reset_password)
        -> update password user terkait.
      - Untuk admin: TIDAK pakai ini — admin reset password lewat
        broker email bawaan Laravel (Password::sendResetLink /
        Password::reset), bukan lewat OTP WA.

## D. Controllers
  [ ] Modules\Auth\Controllers\AuthController — SUDAH ADA, khusus
      admin Blade. Review, tambahkan handling error message yang
      lebih baik di view kalau perlu.

  [ ] Modules\Auth\Controllers\ParentAuthController (BARU, API,
      dikonsumsi React lewat Sanctum)
      - POST /api/auth/otp/request -> panggil GenerateOtpAction
        (action_type dari body request: activation/login/
        reset_password)
      - POST /api/auth/otp/verify -> panggil VerifyOtpAction,
        lalu cabang sesuai action_type:
          - activation -> ActivateParentAccountAction -> buat
            token Sanctum -> return AuthenticatedUserResource
          - login -> AuthenticateParentWithOtpAction -> return
            AuthenticatedUserResource
          - reset_password -> ResetPasswordWithOtpAction -> return
            sukses (user diminta login ulang)
      - POST /api/auth/login -> AuthenticateParentWithPasswordAction
        (login pakai password, bukan OTP)
      - POST /api/auth/logout -> revoke token Sanctum aktif

  [ ] Modules\Auth\Controllers\AdminPasswordResetController (BARU)
      - Alur standar Laravel broker: showLinkRequestForm,
        sendResetLinkEmail, showResetForm, reset. Khusus guard
        "web"/admin, pakai email (bukan OTP).

## E. Form Requests
  [ ] RequestOtpRequest — validasi phone_number (format nomor
      Indonesia) + action_type (in: activation,login,reset_password)
  [ ] VerifyOtpRequest — validasi otp_code (6 digit) + phone_number
      atau user context + action_type
  [ ] ParentLoginRequest — validasi phone_number + password
  [ ] AdminForgotPasswordRequest — validasi email
  [ ] AdminResetPasswordRequest — validasi token, email, password
      (+ confirmation)

## F. Notifications
  [ ] Modules\Auth\Notifications\SendOtpWhatsappNotification
      - Class Notification Laravel (via() return ['whatsapp'] atau
        custom channel).
      - Isi pesan: "Kode OTP Anda: {kode}. Berlaku 5 menit. Jangan
        berikan kode ini kepada siapapun."
      - Provider WhatsApp Gateway BELUM ditentukan final (kandidat:
        Fonnte, Watzhap) — buat implementasi dengan interface/
        contract supaya provider gampang diganti nanti tanpa ubah
        banyak kode (mis. WhatsappGatewayInterface dengan method
        send(string $phoneNumber, string $message)).

## G. Middleware
  [ ] EnsureUserIsActive — cek users.is_active di setiap request
      terautentikasi, auto-logout/reject kalau false (untuk kasus
      admin dinonaktifkan di tengah sesi aktif).
  [ ] Terapkan middleware bawaan Laravel `password.confirm` pada
      route sensitif tertentu di modul lain (BUKAN dibuat di sini,
      cukup dicatat sebagai rekomendasi untuk diterapkan nanti di
      route seperti update payment_channels.account_number atau
      cancel invoice).

## H. Rate Limiting
  [ ] Definisikan RateLimiter::for('otp-request', ...) dan
      RateLimiter::for('login', ...) di AppServiceProvider atau
      provider modul Auth — terapkan ke route request-otp dan
      login (baik admin maupun parent) untuk cegah brute force
      dan cegah biaya WA Gateway membengkak akibat spam.

## I. Routes
  [ ] app/Modules/Auth/web.php — SUDAH ADA untuk admin, tambahkan
      route forgot-password/reset-password admin di sini.
  [ ] app/Modules/Auth/api.php (BARU) — daftarkan semua route
      ParentAuthController, group dengan prefix "auth", middleware
      'api' dan rate limiter yang relevan. Register file ini juga
      di AuthModuleServiceProvider (Route::prefix('api')->
      middleware('api')->group(...)).

## J. Resources
  [ ] Modules\Auth\Resources\AuthenticatedUserResource — bentuk
      JSON response setelah login/aktivasi sukses: data user
      (id, phone_number, email), role, dan token Sanctum. React
      butuh ini supaya langsung tahu "siapa saya & akses apa"
      tanpa request tambahan.

## K. Views (khusus admin, Blade — parent TIDAK butuh Blade sama
       sekali karena dia lewat React)
  [ ] Percantik resources/views/modules/auth/login.blade.php dan
      dashboard.blade.php SESUAI keputusan desain visual di bagian
      4 (bukan versi HTML polos yang sudah ada).
  [ ] Buat halaman forgot-password.blade.php dan
      reset-password.blade.php untuk admin.

4. KEPUTUSAN DESAIN VISUAL YANG WAJIB DIIKUTI (UNTUK VIEW BLADE)
----------------------------------------------------------------
- Styling pakai Tailwind CSS murni, TIDAK ada file CSS terpisah
  per halaman (satu resources/css/app.css global).
- Card: rounded-2xl (border-radius ~16px), soft shadow
  (box-shadow: 0 2px 10px rgba(20,20,50,0.06)), BUKAN border tipis
  flat.
- Icon badge: bulat/rounded-square kecil dengan background pastel
  + ikon warna solid di dalamnya (lihat komponen icon-badge yang
  sudah didesain).
- Warna semantik konsisten: hijau = baik/selesai/lunas, kuning =
  perlu perhatian/sebagian, merah = masalah/belum bayar/gagal.
- Icon set: Tabler Icons (class "ti ti-nama-icon").
- Font: Inter atau Plus Jakarta Sans dari Google Fonts.
- Layout admin.blade.php dan component (icon-badge, status-badge,
  admin-sidebar, admin-navbar) ada di resources/views/layouts/ dan
  resources/views/components/ — DI LUAR folder modules/, karena
  dipakai lintas modul.
- View modul Auth tetap di resources/views/modules/auth/... dengan
  pemanggilan dot notation standar (view('modules.auth.login')),
  TIDAK memakai custom view namespace.
- JS spesifik halaman (kalau ada) ditaruh di
  resources/js/modules/auth/{nama-file}.js, di-load lewat
  @push('scripts') + @vite() di Blade terkait, BUKAN inline script.
